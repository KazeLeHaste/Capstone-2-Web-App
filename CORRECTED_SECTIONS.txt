2.7.2.2.8 Algorithm Structure
The Traffic Simulation System adopts a modular orchestration-based algorithmic structure centered on workflow management, data processing, and SUMO integration, rather than custom vehicle behavior models. It leverages the Simulation of Urban MObility (SUMO) engine for microscopic traffic computation and focuses on efficient coordination of simulation execution, real-time monitoring, KPI computation, and automated recommendation generation.
This design ensures reliable, reproducible traffic analysis for Bacoor City and supports flexible experimentation with different management strategies through a web-based platform.

2.7.2.2.8.1 Simulation Workflow Orchestration
The core simulation process follows a workflow-based algorithm that manages the lifecycle of each simulation session. The algorithm performs the following functions:
•	Initializes session data and temporary directories
•	Generates SUMO configuration files based on user-defined parameters and selected network scenarios
•	Launches the SUMO process using the TraCI (Traffic Control Interface) protocol for live data exchange
•	Executes iterative simulation steps, collecting and broadcasting live traffic metrics in real time
•	Parses SUMO's output files (tripinfo, summary, emissions) upon completion
•	Computes analytics and KPIs from the gathered data and stores them in the system database
•	Sends live updates and final results to the user interface via WebSocket communication
This modular workflow ensures process isolation, robust error handling, and efficient data transfer between the backend and the SUMO engine.

2.7.2.2.8.2 Key Performance Indicator (KPI) Computation
Following each simulation, the backend algorithm calculates Key Performance Indicators that quantify the overall traffic efficiency and sustainability.
Metrics include:
•	Average Travel Delay – Derived from total time loss per trip
•	Throughput – Number of successfully completed trips
•	Average Queue Length – Based on cumulative waiting steps over simulation intervals
•	Average Speed – Mean velocity across all vehicles per interval
•	Congestion Index – Ratio of time loss to total trip duration
•	Emission Levels – Aggregated CO₂, NOx, PMx, and fuel consumption from SUMO's emission reports
•	Safety Score – Computed inversely from total collisions and teleports recorded
These KPIs form the analytical foundation for generating actionable insights and strategy recommendations.

2.7.2.2.8.3 Recommendation Generation Engine
The system integrates a rule-based recommendation algorithm that analyzes KPI results and automatically suggests optimal interventions for congestion management, safety improvement, and environmental sustainability.
Each recommendation entry includes a type, priority, description, target metric, and expected impact.
Sample decision rules include:
•	Triggering adaptive signal control when congestion exceeds 30%
•	Suggesting road capacity improvements when average speed drops below 20 km/h
•	Encouraging eco-routing or public transport adoption for high emission outputs
•	Optimizing signal timing when queue lengths become excessive
•	Recommending speed limit reviews for low safety scores
All recommendations are prioritized according to impact severity, ensuring that the most critical interventions are presented first.

2.7.2.2.8.4 Data Management and Communication
The backend employs asynchronous data handling through WebSocket protocols for continuous real-time communication between the SUMO engine, the Flask server, and the frontend interface.
During simulation:
•	Live metrics are broadcast to the visualization dashboard
•	Completed data are stored in structured databases for retrieval and reporting
•	Intermediate data (tripinfo, summary, emissions) are parsed, transformed, and cached to minimize latency
This data-centric approach ensures both performance efficiency and transparency throughout the simulation process.

2.7.2.2.8.5 SUMO Integration and Control Interface
The algorithmic structure relies on the TraCI (Traffic Control Interface) to control SUMO dynamically during execution. Through this interface, the backend can:
•	Trigger simulation steps in real time
•	Retrieve live vehicle, lane, and traffic light data
•	Adjust configurations on-the-fly (e.g., phase timing, network changes)
•	Gracefully terminate or resume sessions based on system commands
This integration bridges the backend orchestration with SUMO's robust simulation capabilities, providing a flexible platform for experimentation and analysis.

2.7.2.2.8.6 System Intelligence and Extensibility
While the current implementation utilizes rule-based analytics, the architecture is modular and designed for future integration of AI-driven optimization modules, such as:
•	Reinforcement learning for adaptive signal timing
•	Predictive analytics for congestion forecasting
•	Automated calibration of traffic parameters using machine learning
This forward-compatible structure ensures long-term scalability and adaptability for research and urban planning applications.

2.7.2.2.9 AI Tools and APIs
To enhance analytics accuracy, recommendation generation, and modular system integration, the Traffic Simulator System incorporates artificial intelligence (AI) components and RESTful/WebSocket APIs within its backend architecture.

2.7.2.2.9.1 AI-Assisted Development (ChatGPT & Copilot Integration)
AI-assisted tools such as ChatGPT (OpenAI GPT-4) and GitHub Copilot supported the development lifecycle by assisting in:
•	Refining algorithm workflows (simulation orchestration, KPI computation, recommendation logic)
•	Auto-generating configuration templates and Python/React code snippets
•	Optimizing database schema design
•	Enhancing documentation and code readability

While these AI tools were used only during the development phase, not at runtime, they significantly accelerated prototyping, debugging, and system design consistency.

2.7.2.2.9.2 Rule-Based Recommendation Engine (AI Logic Layer)
Instead of deploying complex machine learning models, the system integrates a rule-based AI logic that generates intelligent traffic management recommendations based on calculated KPIs.
The algorithm evaluates metrics such as congestion index, average speed, emissions, queue length, and safety score.
Sample AI-driven responses include:
•	"High congestion detected — consider adaptive signal control."
•	"Low average speed — evaluate road capacity or re-routing."
•	"High CO₂ emissions — encourage eco-routing or public transport incentives."
This AI component ensures explainable, transparent decision support aligned with real-world traffic management principles.

2.7.2.2.9.3 RESTful and WebSocket APIs (Flask-based Backend)
The Flask backend exposes RESTful APIs and real-time WebSocket endpoints to enable seamless data flow between the frontend, backend, and SUMO simulation engine.
These services manage configuration, session control, analytics, and live simulation monitoring.
RESTful API Endpoints include:
•	Configuration management (/api/configurations)
•	Network retrieval (/api/networks)
•	Session control (/api/sessions, /api/simulations/start, /api/simulations/stop)
•	Analytics retrieval (/api/analytics/...)
•	Data export (/api/export)
WebSocket Events (Socket.io) support:
•	Real-time updates (live_data, simulation_status, simulation_complete)
•	Multi-session management
•	Live synchronization between SUMO engine and frontend dashboards
This hybrid API structure ensures low-latency performance and modular scalability for future feature expansion.

2.7.2.2.9.4 Visualization and Frontend Integration (React + Recharts)
The React frontend integrates with backend APIs to visualize simulation outputs in real time.
Using Recharts, the system renders dynamic dashboards showing:
•	Live vehicle statistics (speed, waiting time, vehicle count)
•	Emission trends and congestion indexes
•	KPI dashboards and comparative charts
WebSocket-driven updates guarantee continuous synchronization between SUMO simulation data and the displayed analytics without requiring page reloads.

2.7.2.2.9.5 External Engine Integration (SUMO + TraCI API)
The system's backend communicates with the Simulation of Urban MObility (SUMO) engine through the TraCI (Traffic Control Interface) API.
This Python-based API enables real-time control and data collection from the simulation environment, such as:
•	Vehicle speed, waiting time, and emissions retrieval
•	Intersection signal control
•	Step-by-step simulation management
TraCI integration transforms SUMO into a controllable micro-simulation backend, allowing the AI and analytics modules to react dynamically to live traffic conditions.


2.7.3 Testing Procedures
A structured testing framework was employed to validate the Traffic Simulator's functionality, usability, data accuracy, and SUMO integration workflow. Testing ensures that the system performs reliably across all modules—from network selection and configuration to live analytics and recommendation generation.
These procedures are designed to guide end-users such as traffic analysts, planners, and enforcement officers in accurately executing simulations of pre-configured traffic scenarios and interpreting simulation outcomes for data-driven decision-making.

Phase 1: Configuration Setup
1.	Launch the simulator via its designated web application URL (http://localhost:3000).
2.	Navigate to the Configuration Page to define simulation parameters.
3.	Set essential parameters including:
    •	Begin time and end time (simulation duration)
    •	Step length (simulation granularity)
    •	Traffic scale (vehicle density multiplier)
    •	Vehicle types (passenger cars, buses, jeepneys, trucks, motorcycles, bicycles)
    •	Traffic control method (existing signals, fixed-timer, adaptive, buhos/counterflow, custom timing)
4.	For fixed-timer control, configure cycle length, green time, yellow time, and all-red time.
5.	Set advanced SUMO parameters such as lateral resolution (sublane model), seed value, collision action, and timeout thresholds.
6.	Save the configuration for reuse in future simulations.
7.	Verify that configuration parameters are stored correctly in the SQLite database and can be loaded for subsequent sessions.

Phase 2: Network Selection
1.	Navigate to the Network Selection Page to choose a traffic scenario.
2.	Review the seven (7) pre-configured Philippine traffic networks representing Bacoor City locations:
    •	Bayanan Area
    •	Jollibee Molino Area
    •	Perpetual Molino Area
    •	SM Bacoor Area
    •	SM Molino Area
    •	St. Dominic Area
    •	Statesfield Area
3.	Examine network metadata including node count, edge count, and junction count.
4.	Select the desired network for simulation.
5.	Optionally, use the OSM Scenario Importer tool to add new networks created externally using SUMO's OSM Web Wizard.
6.	Confirm that the selected network loads properly and all required SUMO files (.net.xml, .rou.xml, .sumocfg) are accessible.

Phase 3: Simulation Execution and Monitoring
1.	Navigate to the Simulation Page with the selected configuration and network.
2.	Click "Launch Simulation" to initialize the SUMO process via the Flask backend.
3.	Observe the SUMO GUI window opening on the desktop, displaying real-time vehicle movements and traffic signal operations.
4.	Monitor real-time metrics in the web dashboard via WebSocket updates, including:
    •	Current simulation time and step
    •	Loaded, departed, running, and arrived vehicle counts
    •	Mean speed, mean waiting time, and mean travel time
    •	Collision events and teleported vehicles
5.	Review live charts showing speed over time and vehicle count progression.
6.	Optionally pause, resume, or stop the simulation using control buttons.
7.	Wait for simulation completion, at which point SUMO terminates and output files are generated.
8.	Verify that the session status updates to "completed" and analytics processing begins automatically.

Phase 4: Analytics Review and Data Interpretation
1.	Navigate to the Analytics Page to review post-simulation results.
2.	Select the completed session from the session dropdown.
3.	Review Key Performance Indicators (KPIs) displayed in dashboard cards:
    •	Average Travel Delay (seconds)
    •	Throughput (completed trips)
    •	Average Queue Length (vehicles)
    •	Average Speed (km/h)
    •	Congestion Index (ratio)
    •	Total Fuel Consumption (liters)
    •	Total CO₂, NOx, and PM emissions (grams)
    •	Safety Score (0-100 scale)
4.	Examine analytical charts and graphs:
    •	Line charts: Speed over time, waiting time trends
    •	Bar charts: Vehicle arrivals per time interval
    •	Pie charts: Vehicle type distribution
    •	Area charts: Emissions accumulation over time
5.	Review AI-generated recommendations sorted by priority, including:
    •	Traffic control strategy suggestions
    •	Signal timing optimization proposals
    •	Capacity expansion evaluations
    •	Environmental mitigation strategies
    •	Safety improvement recommendations
6.	Use the Session Comparison tool to compare KPIs across multiple simulation runs with different configurations or control methods.
7.	Export simulation data in desired formats:
    •	CSV: Trip data, time series data, KPI summaries
    •	JSON: Complete session data with nested analytics
    •	XML: Raw SUMO output files
    •	PDF: Comprehensive report with charts and recommendations

Phase 5: Session Management and Termination
1.	Review active and completed sessions in the Home Page or Simulation Page.
2.	For multi-session scenarios, verify that concurrent simulations operate on isolated resources with dedicated TraCI ports (8813, 8814, 8815, etc.).
3.	Stop any running simulations from the backend interface, ensuring SUMO processes terminate cleanly.
4.	Confirm that all session data, including configurations, live data, trips, time series, KPIs, and recommendations, are properly saved in the SQLite database.
5.	Close the simulator application securely after ensuring all analytics and reports have been generated and exported as needed.

This structured testing methodology validates each stage of the workflow, ensuring end-users can efficiently configure, execute, monitor, analyze, and export traffic simulation results for strategic management and policy formulation.

2.7.4 Deployment

•	TraCI modules are configured with dynamic port allocation (8813+) for multi-session execution.

•	Controlled pilot simulations are conducted to validate SUMO-Flask-React synchronization through WebSocket channels.

The pilot group consisted of three (3) participants with diverse expertise: one (1) BTMD officer with strategic traffic management responsibilities, one (1) traffic enforcer with field operation experience, and one (1) IT expert with software evaluation background. Three (3) additional traffic enforcers participated in preliminary interviews to provide operational context and requirements input.

The session was held in a controlled testing environment equipped with standard desktop systems (Windows 10/11, Google Chrome browser) running the Traffic Simulator as a localhost web application (frontend on port 3000, backend on port 5000) with SUMO 1.19.0+ installed.
